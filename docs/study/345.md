# 345 — Chain: read each stage's verdict so quoted text cannot stop a healthy run or pass a failed one

| Finding | Level | Fix applied |
| --- | --- | --- |
| Confirmed decisions allowed only "a leading bullet or quote marker", but the #242 regression the ACs require still passing is a heading (`## VERIFIED …`, 4bad10b) | Plan-spec | Widened the tolerated marker set to include headings (473a4ae) |
| `jq -e .` exits 1 on valid `null`/`false`, so the pre-existing parseability check would report either as "reply was not JSON" rather than the new not-an-object reason | Codebase | Parseability tested with `jq -e 'type'`, object-ness separately (473a4ae) |
| "Read the verdict by position" was implemented as position *plus a start anchor*, which still let one line carry a success verdict and a contradiction (`VERIFIED branch=x, FAILED reason=suite red`); because the failure pattern is `^FAILED` it cannot see a `FAILED` mid-line, so this read as a pass and would raise a PR off a failed `/verify` — the exact defect the issue was raised to remove, one line lower down. Two reviewers found it independently; the matrix missed it because its nearest case put the trailing sentence on a *separate* line | Execution | Success patterns anchored at both ends over a non-empty payload; eight cases added, including the four hedged shapes and the empty payload |
| Stripping leading whitespace without limit let a four-space or tab indent — markdown's other code block — lift a quoted verdict into last place, the one way a quotation can fake position, while the docs asserted a fenced verdict is unreadable | Execution | Indent strip bounded to three spaces; a case per indent form |
| The branch's own contract ("nothing else on that line and nothing after it") was stated in all four prompts but enforced for neither same-line trailing text nor `build.md`/`raise-pr.md`'s precondition stops, which still emitted bare English — so a chain run on a `main` with unpushed commits loses the real reason to `no readable verdict` and parks the issue with a non-reason | Plan-spec | Every STOP in all three prompts now ends on a `FAILED reason=` line; `verify.md` states the rule once for all eleven of its stops |
| A test named "a reason that legitimately ends in a backtick keeps it" never reached the emphasis-strip code it was written for, because its input had no opening emphasis run — a false green over the exact logic it named | Execution | Three cases added that do reach it; the balanced-wrap case preserves the backtick and the unbalanced one is pinned as the documented limit |
